### 2.10?? 孤児規則の緩和: impl の置き場所を 1 つに決める (2026-11-21、利用者の決定、仕様 3.2)

- 規則 (`check::orphan_violation`、旧い検査と TAST 規則 `tast_rules/impl_sig.rs` の両方が使う): 対象の型 `T` がこのパッケージの名義型なら `T` のモジュール、そうでなく、トレイト `Tr` がこのパッケージのものなら `Tr` のモジュール。どちらも部外なら置けない (E2043)。違う場所は E2043 で正しいモジュールを名指す。基本型は部外なので、トレイトのモジュールだけ。
- 旧い規則は「`Tr` がこのパッケージならどこでも」だったので、`impl` が `Tr` のモジュール以外 (同じパッケージの別モジュール) にあると、今は E2043 になる。型の側の `impl` を型のモジュール以外に置いていた試験の入力 (`check_diag` の `TRAIT_SIDE_*`) は、置き場所を移した。自分の型 `t.ty.P` の impl は型のモジュールに置くので、その試験の `ksn get` の FQN を `t.tr.Show.t.ty.P.show` から `t.ty.P.show` に変えた (ほかの期待値は変えていない)。
- メソッド探索: 依存のトレイトのモジュールに置いた impl は、利用側が `import` していなくても見つかる (既に成り立っていた。`tests/orphan_rule.rs` で確かめる)。インタプリタと native (`ksn build --backend llvm`) の出力が一致する。
- 試験: `stage0/tests/orphan_rule.rs` (2 パッケージ: ライブラリ `orl` のトレイトを `alloc.vec.Vec<u32, std.alloc.System>` と `u32` に trait 側で実装し、app が使う。型側の正しい置き場所、違う置き場所 (別モジュール・型のモジュールに対するトレイト側・両方部外・同じパッケージの別モジュール) の拒否)。
- パッケージの同一は、モジュール名の最上位の成分で決める (`core`・`alloc`・`std` は標準ライブラリの 1 つのパッケージ)。標準ライブラリの中の impl は、この検査の対象外 (移行の前の配置を残す)。`std.json` の `ToJson` / `FromJson` (型側と別モジュールに置いた 28 件) と `alloc.arena` の `Clone`・`alloc.collections` の `Iterator` は、新しい規則では違反になる。直すなら `spec/stdlib` の移動が要る (次の課題)。
- 残り: blanket impl (型パラメータへの impl) は従来どおり検査の対象外 (トレイトのモジュールにだけ置ける仕様は未検査)。標準ライブラリの配置の移行 (上の 2 件)。
