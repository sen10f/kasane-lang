# 既知の制限

この文書は、ベータ版 `0.1.0-beta.1` の使用时と実装上の制約をまとめます。

## ホストと配布対象

- macOS でのホスト実行と macOS 向けビルドには対応していません。動作確認済みのホストは Linux（x86_64）です。
- Windows 向け実行ファイルは Linux からクロスコンパイルできますが、Windows 上のホスト開発環境には対応していません。
- 配布用のビルド済みバイナリは x86_64 Linux（Arch、Debian 12 以降。要る glibc は 2.30 以上）向けです。ライセンスは MIT または Apache-2.0（`LICENSE-MIT` / `LICENSE-APACHE`）。

## パッケージレジストリ

中央の公共パッケージレジストリはありません。依存パッケージは、`kasane.toml` に記述したローカルパス、または Git の URL とコミットハッシュで取得します。バージョン範囲の指定はありません。`ksn publish --registry <URL>` でレジストリ（またはパス）へ公開でき、`ksn update` と `ksn vendor` は利用できますが、`vendor` の実ネットワーク動作は未検証です。

## S4 の検査器移行

S4（検査器を TAST（型付き AST）へ移し、KIR への下ろしを TAST から行う作業）は統合済みです（コミット `97178d39`）。`KSN_CHECKER` の既定は `s4`（新しい検査 TAST）。`KSN_CHECKER=old|new|shadow` は 1 リリースだけ受け付けますが、同じ検査器が走り非推奨の旨を出力します。旧い検査器は取り外されました。

通ってはいけないコードは `stage0/tests/data/unsound/` に 1 ファイル 1 ケースで置き、まだ塞げないものは `stage0/tests/check_diag.rs` の `KNOWN_HOLES` に載せる慣習です。

## 手書きの `Drop` の実行の範囲

手書きの `impl core.ops.Drop`（仕様 4.4）の `drop` は、スコープの終わり（宣言の逆順。外側の `drop` のあとに欄を宣言順）・再代入で捨てる古い値・`core.mem.drop`・文の終わりの一時値で呼ばれます。`return` / `?` / `break` / `continue` と、`with` の本体の出口でも、抜けるスコープの分が呼ばれます。panic とプロセスの終了では呼ばれません。move 済みの値は呼びません（条件付きの move は実行時の印で判断します）。値を `spawn` のクロージャへ move すると、スレッドの中で破棄されます。

実行は KIR（`ksn run` / `ksn test` は VM、`ksn build` はネイティブ）が担います。木走査は値の所有を追跡しないので、手書きの `Drop` を持つパッケージは `ksn run` / `ksn test` でも常に VM で走り、KIR に下ろせない形のときは木走査へ退避せず、理由を出して失敗します。型パラメータを持つ型の `Drop` は型引数ごとに単相化して呼びます。`Fn` / `FnMut` のクロージャへ `move` した値は、クロージャを作ったスコープの終わりで破棄され（クロージャがそのスコープの外へ出る形は対象外）、呼ばれなかった `FnOnce` の環境も同じ所で破棄されます。KIR に下ろせない形（たとえば `Result` を欄に持つ構造体）が含まれるときは、理由を出して失敗します。

`Drop` を持つ型の欄を `let s = g.s` で取り出す形は E3002 で拒みます。`--engine=tree` を明示しても、手書きの `Drop` を持つパッケージは VM で走ります。デバッガ (`ksn debug` / `ksn dap`) は木走査なので、手書きの `Drop` を持つパッケージは E9031 で拒みます。

## 既知の検査の穴

通ってはいけないコードは `stage0/tests/data/unsound/` に 1 ファイル 1 ケースで置き、まだ塞げないものは `stage0/tests/check_diag.rs` の `KNOWN_HOLES` に載せる慣習です（`KSN_CHECKER=old|new|shadow` も非推奨で、1 つの検査器だけが走ります）。

## インタプリタへの退避

ネイティブ実行ファイルへ下ろせない機能を使った場合や、必要なコンパイラがない場合、`ksn build` は理由を求めてインタプリタ同梱のバンドルへ退避することがあります。通常のデバッグビルドではこの退避を許しますが、リリースビルドでは E9040 として失敗します。リリースで退避を明示的に許す場合は `--release --allow-bundle` を指定してください。

`ksn test --both` も、LLVM による比較ができない場合はバンドルを使います。この場合、比較対象はネイティブ機械語ではなく、インタプリタ同梱の実行環境です。

## spawn の失敗

スレッドを作れずに `std.thread.spawn` が失敗したとき、ネイティブと VM は `Err(SpawnError)` を返さず、`spawn failed: ...` の panic でプログラムを止めます (終了コード 101)。クロージャを返せるのは木走査 (`--engine=tree`) だけです。
