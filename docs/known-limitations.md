# 既知の制限

この文書は、ベータ版 `0.1.0-beta.1` の使用时と実装上の制約をまとめます。

## ホストと配布対象

- macOS でのホスト実行と macOS 向けビルドには対応していません。動作確認済みのホストは Linux（x86_64）です。
- Windows 向け実行ファイルは Linux からクロスコンパイルできますが、Windows 上のホスト開発環境には対応していません。
- 配布用のビルド済みバイナリとライセンスは未確定です。README の各項目を参照してください。

## パッケージレジストリ

中央レジストリと `ksn publish` はありません。依存パッケージは、`kasane.toml` に記述したローカルパス、または Git の URL とコミットハッシュで取得します。バージョン範囲の指定はありません。`ksn update` と `ksn vendor` は利用できますが、`vendor` の実ネットワーク動作は未検証です。

## S4 の検査器移行

検査器を TAST（型付き AST）へ移す S4 の作業は進行中ですが、新検査器はまだ既定ではありません。通常の `ksn check` は従来検査器と KIR の検査を併用します。

2026-11-19 時点の進捗は次のとおりです。

- S4A では、正しいコードに新検査器だけの診断（`new_only`）を出さないところまで進みました。
- S4C では、明示した型引数の効果を実体化し、E4001 / E4002 の `old_only` を 0 件にしました。
- 残りの主な `old_only` は、E2042 が 25 件、E3031 が 23 件、E5001 が 19 件、E5003 が 16 件です。E2044 など、型推論や名前の解決の段に残す項目もあります。

検査器は 1 つに一本化されました (`KSN_CHECKER=old|new|shadow` は非推奨で、同じ検査器が走ります)。

## 既知の検査の穴

`stage0/tests/check_diag.rs` の `KNOWN_HOLES` に、次の 6 件が登録されています。これらは現在 `ksn check` を通るため、安全性が保証されたコードとして扱わないでください。

| 名前 | 内容 |
| --- | --- |
| `impl_sig_method_generics_count` | トレイト実装のメソッドについて、型パラメータの個数がトレイト宣言と一致するか 검사しません。 |
| `impl_sig_method_generics_bound` | トレイト実装のメソッドに追加された型パラメータ境界を検査しません。 |
| `impl_sig_lifetime_ret` | トレイト実装のメソッドの戻り値と、トレイト宣言の参照の寿命の対応を検査しません。 |
| `len_of_linear_array_then_consumed` | 線形な要素を持つ配列の `len` を取ったあと、その配列を消費する形を検査しません。 |
| `return_local_tuple_destructure` | 局所値の借用を含むタプルを分解して返す形を検査しません。 |
| `return_local_option_tuple_destructure` | 局所値の借用を含む `Option` のタプルを分解して返す形を検査しません。 |

## インタプリタへの退避

ネイティブ実行ファイルへ下ろせない機能を使った場合や、必要なコンパイラがない場合、`ksn build` は理由を求めてインタプリタ同梱のバンドルへ退避することがあります。通常のデバッグビルドではこの退避を許しますが、リリースビルドでは E9040 として失敗します。リリースで退避を明示的に許す場合は `--release --allow-bundle` を指定してください。

`ksn test --both` も、LLVM による比較ができない場合はバンドルを使います。この場合、比較対象はネイティブ機械語ではなく、インタプリタ同梱の実行環境です。
