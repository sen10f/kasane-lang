source = "git+https://example.org/ranged.git#0123456789abcdef0123456789abcdef01234567"
version = "1.4.0"
hash = "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
deps = []
unsafe_modules = []
```

  - `source` is not the URL of the manifest but the **resolved commit**. It is `git+URL#COMMIT`, and moving a `tag` does not change a locked build.
  - `version` is the `package.version` of the selected package's `kasane.toml`. Required for both registry and Git versions.
  - Entries originating from a registry also record `registry = "https://example.org/kasane-registry.git"`, preserving the origin of the index.
  - `hash` is, as before, the SHA-256 of `kasane.toml` + `src/**/*.ksnl`. It fixes not only the commit ID but also the distributed bytes.
  - Constraint expressions are not duplicated in the lock. The checker confirms that the selected `version` satisfies the manifest's constraints.
  - A `path` dependency has only `source = "path+..."` and `deps`. Version, hash, and API are not recorded.
  - Versions 1 and 2 are read, and migration to version 3 is done by `ksn lock --upgrade` or the next `ksn update`. Unknown lock keys are not silently ignored.
  - Only `ksn update` and `ksn lock --accept` write the lock. A directly edited lock is E0020 / E9021 as a diff from canonical.
- A `git` dependency of version 2 (`version = 2`) records, in addition to `hash`, the **full text of the canonical headers of public definitions** as `[[package.api]]` (`fqn` and `sig`, in FQN byte order), records the dependency's `[unsafe] modules` in `unsafe_modules`, and the dependency's C libraries of `[native]` in `native_libs` (the `static` paths and `dynamic` names together in byte order; not written if empty) (3.8). The targets of recording are the `pub` `fn` / `type` / `enum` / `trait` / `const` / `static` / `extern` (for `type` / `enum` / `trait`, the whole including fields, variants, and methods), `impl` lines, and the headers (including `uses` / `panics`) of the trait's `impls` functions. `path` dependencies are not recorded. Transitive dependencies are each recorded too (the lock is a flat sequence of `[[package]]`). `ksn check` / `build` / `test` / `run` compare the dependency's current public headers with the record, and stop with E9060 if effects have widened (`uses` increased, `panics never` → `may`, `unsafe_modules` increased, `extern`s increased, `native_libs` increased), E9061 if a signature changed or a public definition vanished, and E9062 if things narrowed, public definitions increased, or `unsafe_modules` or `native_libs` decreased (all fatal. The diff between the earlier and current headers is shown). Acceptance is by `ksn lock --accept <dependency>` (`--accept --all` for all, `--diff` shows only the diff without writing). `ksn update` updates `source` / `hash` / `deps`, but does not rewrite the `api`, `unsafe_modules`, and `native_libs` that have records (it writes only the first time for dependencies without records). A version 1 lock can be read (signatures are not compared), and is raised to version 2 by `ksn lock --upgrade`. In version 2, if a `git` dependency has no record, it is E9021.
- A `git` dependency has `source = "git+<URL>#<rev>"` and `hash`. A `path` dependency has `source = "path+<relative path>"` (always a normalized path relative to the root package's directory. `..` allowed, `/` separators), and if the `kasane.toml` of a `git` dependency target has a `path` dependency it is E9013 (a `git` dependency target can have only `git` dependencies). A `path` dependency has no `hash` (not verified, so that the build does not fail at every edit).
- Computing `hash`: the targets are the `kasane.toml` directly under the package root and the `*.ksnl` files under `src/` (`vendor/`, `target/`, and `kasane.lock` are not included). For a `git` dependency the package root is the repository root (specifying a subdirectory is not allowed). Paths are relative to the root (no leading `./`, `/` separators), sorted in UTF-8 byte order. Each file is concatenated as "path, 0x00, content length (u64 LE), raw bytes" and the SHA-256 is taken, written as `sha256:` + 64 lowercase hex digits. The content is kept as bytes (no newline conversion. CRLF is E0001 in 3.7). A symbolic link is E9016.
- A mismatch between `kasane.toml` and `kasane.lock` (a discrepancy in the set of dependencies, `source`, `version`, or `deps`) is E9021, and a hash mismatch of a `git` dependency is E9022, and `ksn check` / `build` fail. If there is one or more dependency but no lock, it is not created, and E9020 prompts for `ksn update` (with 0 dependencies it passes without a lock. `ksn new` generates a lock without dependencies (only `version = 1`)). Updating the lock is done by `ksn update [<name>]` and `ksn lock` (only recording signatures).
- In the whole dependency graph, a package of the same name has only one `source`. If a different `source` appears, it is E9014 (versions are not reconciled automatically). If the `name` in the dependency's `kasane.toml` does not match the dependency key, it is E9011.
- `check` / `build` / `test` / `run` / `vendor` use only the commits recorded in `kasane.lock`. They do not go to the network and do not re-select range candidates. Only `ksn update` re-selects candidates from the registry snapshot and the Git remote tag list. Constraints on the same dependency name are intersected, candidates are compared in SemVer numeric order, and the **greatest version** that satisfies the conditions is selected. Even if a child dependency's constraints contradict the parent's selection after selection, it does not backtrack to another parent version, and reports the conflicting constraints and versions.
- `ksn vendor` re-fetches `git` dependencies (including transitive ones) from the source and copies them to `vendor/<name>/` (`.git` is not included). If there is a record in `kasane.lock` and the hash of the fetched content differs from it, it fails with E9022 without copying. `ksn check` / `build` / `test` / `run` read `git` dependencies from `vendor/<name>/`, or if absent from the implementation's cache (what `ksn update` fetched), and if neither exists, E9010 prompts for `ksn vendor` / `ksn update`, and they do not go to the network. Only `ksn update` and `ksn vendor` go to the network. A `git` URL is one that `git clone` accepts (`https://` `ssh://` `file://`, local paths), a registry URL is HTTPS or SSH, and empty or option-like ones are E9008. `path` dependencies are outside vendoring and always prefer `path`. Build artifacts go in `target/`.
- The minimal registry uses an index with a Git backend. No central HTTP API is needed, and the current Git fetching, cache, and vendor can be reused.

```
kasane-registry.git/
  index/foo.json
  index/bar.json
```

  - JSON is separated per package, so the publications of different packages do not conflict.
  - `index/<name>.json` is an array in ascending order of version. The shape of an entry is only the following sequence.

```
{"version":"1.2.3","tag":"v1.2.3","repository":"https://example.org/foo.git","commit":"0123456789abcdef0123456789abcdef01234567","hash":"sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","owner":"https://example.org/foo.git","yanked":false}
```

  - `version` is confirmed to match the `package.version` of the index and the commit. `tag` is only `vMAJOR.MINOR.PATCH`. `repository` is the source repository, and `owner` is the canonical source repository URL held by the first publisher.
  - The same name/version cannot be re-pointed. A correction is made by yanking and issuing a new version. A version with `yanked` set to true is not selected in new resolutions, but when an existing lock has the exact commit it stays usable to preserve offline reproducibility.
  - Registry package names are globally unique, and the first adopter becomes the owner. `core`, `alloc`, `std`, language reserved words, and existing reserved names are also rejected in the registry. Re-publishing an existing name from a different repository is rejected.
  - The required integrity of the MVP is the triple pinning of an immutable commit + the distribution SHA-256 + the lock. The same hash is also put in the index entry. The registry transport presupposes HTTPS/SSH and a trusted registry URL. SHA-256 is tamper detection, and does not substitute for trust in the registry operator.
- `core` / `alloc` / `std` are implicit dependencies bundled with the compiler, and are not written in `kasane.toml` / `kasane.lock` (the version is fixed by the compiler version). These three names are reserved as package names, and a user package claiming one is E9004. User packages can reference all three (an exception to "dependencies only" in 3.3).

### 8.2 Minimal configuration of the standard library

- `core` (independent of the OS and allocators): `core.num` (methods of primitive types), `core.bool`, `core.char`, `core.str`, `core.slice`, `core.array`, `core.cmp` (`PartialEq` `Eq` `PartialOrd` `Ord` `Ordering`), `core.ops` (`Fn` `FnMut` `FnOnce` `Drop` `Copy` `Clone`), `core.marker` (`Send` `Sync`), `core.mem` (`drop` `swap` `replace`), `core.check` (assertions for tests: `eq` `is_true`. The method names are `debug_fmt` / `display_fmt`), `core.hash` (`Hash` and hashers of fixed algorithms), `core.iter` (`Iterator` `range` `Map` and others), `core.option`, `core.result`, `core.sync` (atomic types), and `core.ptr` (raw-pointer operations. `.ksnl`). Math functions are implemented in `core.num` itself. The arithmetic, conversions, and bit reinterpretations of `core.num` / `core.bool` / `core.char` (`checked_add`, `from_bits`, etc.) are compiler built-ins and have no source bodies. The atomic-type methods of `core.ptr` and `core.sync` are also compiler built-ins (no body). A concrete hasher `core.hash.Fnv64` (fixed algorithm) is provided.
- `alloc` (depends only on `core`): `alloc.alloc` (the trait `Allocator`: `alloc` / `realloc` are `uses [alloc] panics never` and return `Result`, and `dealloc` is `uses [] panics never`), `alloc.boxed`, `alloc.vec`, `alloc.string`, `alloc.collections` (`HashMap` is in insertion order, `BtreeMap`, `VecDeque`). - `std` (the OS-dependent parts are `std.sys.*`): `std.io` (`Read` `Write`, console), `std.fs`, `std.net`, `std.thread` (`spawn` `JoinHandle`), `std.sync` (`channel` `Sender` `Receiver`) (these two hold manual `impl`s of `Send` / `Sync` and raw pointers, so they are written in `unsafe`-permitted modules (the bundled `std` is implicitly permitted)), `std.process` (`exit` `abort`, running external commands `Command` `Child`), `std.env`, `std.time`, `std.rand`, `std.task` (the cooperative executor. 5.6), `std.json`, `std.http` / `std.tls`, `std.path`, `std.datetime` / `std.log`.
- The OS-dependent parts are placed in `std.sys.<name>`, in modules separate from the public-API modules. References to `std.sys.` from packages other than `core` / `alloc` / `std` are E1124. `std.alloc` provides the `System` allocator. Runtime symbols (those whose `link` name begins with `ksn_rt_`. E.g. `ksn_rt_panic`) are provided by the runtime bundled with the compiler (implemented in Rust. Panic output, stack-overflow detection, `entry` startup), and are resolved by linking in `ksn build` and as interpreter built-ins in `ksn run`. Users cannot use `ksn_rt_` in `link`, and doing so is E1030. `core.panic.panic` calls it via an `extern` declaration inside `core.panic`, and `std.rt` also only calls it, and there is no symbol export from Kasane.
- Example of the layer order of modules inside `core`: `marker` / `ops` → `fmt` → `cmp` → `option` / `result` / `hash` / `iter` ... (`fmt` comes before `cmp` because `cmp.Ordering` derives `Debug`) (references to prelude names are not counted as edges of cycle detection. 3.6).
- The dependency direction is `std` → `alloc` → `core` (the reverse is an error. Checked by `import`s and FQN references inside the bundled packages). The `Option` / `Result` of the prelude (4.2) are handled as the language's built-in name resolution, not as re-exports of `core.option` / `core.result`. Individual API signatures are normatively those of `spec/stdlib/` in 8.3.

- Asynchronous sockets of `std.net` (`net.ksnl`, the effects are `io.net` and `suspend`. `設計_多重化したネット.md`): `TcpListener.accept_async(&self) -> Result<TcpStream, std.net.Error>`, `TcpStream.read_async(&mut self, buffer: &mut [u8]) -> Result<usize, std.io.Error>`, and `TcpStream.write_async(&mut self, buffer: &[u8]) -> Result<usize, std.io.Error>` have the same shapes as the blocking `accept` / `read` / `write`, and are suspension points with `uses [io.net, suspend]`. If the socket cannot be read or written, inside the executor of `std.task` (`block_on`) that task is suspended and other tasks are run. When ready it is resumed and continues reading or writing (`read_async` reads what has arrived, and `write_async` writes up to 16384 bytes and returns the number written. As with the blocking versions, it may return a partial write). A borrow (`&mut buffer`) is an argument of the call, so it can be held across the suspension (outside the scope of E3050). Deadlines are governed as they are by the existing `set_read_timeout` / `set_read_deadline` etc., and when a deadline expires it is `Err(std.io.Error { kind: TimedOut, .. })` (`std.net.Error { code: 110 }` for `accept_async`). Called outside the executor (outside `block_on`), it does not suspend and waits just like the blocking version. Only these three are public, and the waiting mechanism (Linux epoll), fd numbers, and EAGAIN are not shown to users. On Linux native (LLVM), a single-threaded executor waits on many fds with epoll (`std.task.wait_io` is an internal suspension point and has no `pub` in `.sig`). The tree walker checks with `poll` and yields to other tasks (deterministic, and the output matches native). On Windows, native is E9040 (IOCP / WSAPoll are future work), and wasm32 does not support `std.net` at all. The closures of `std.task.block_on` / `spawn_local` permit `linear` (so that a `TcpStream` can be taken in by `move` and passed to a per-connection task. A task runs to the end, so the body consumes the captured value). The `listen` backlog is 1024.
- `TcpStream.fd()` of `std.net` is a read-only `pub` method returning the OS fd (`std.tls` passes it to `SSL_set_fd`). The `descriptor` field is private, and it is impossible to forge a `TcpStream` with an arbitrary fd from outside (a hole filled in 8.3). The tree walker also returns the OS fd (the same number as native).
- `std.http` (`spec/stdlib/std/http.ksnl`. A norm written entirely in Kasane, with no `.sig`. Parsing and assembling use `alloc`, and reading and writing use `io.net`): parsing HTTP/1.0 and 1.1 requests and assembling responses. `Decoder.new(max_head: usize, max_body: usize)` is a parser that holds leftover bytes; bytes are added with `feed(&[u8])` and taken out one at a time with `next() -> Result<Option<Request>, Error>` (`None` if insufficient, and leftovers remain. Several requests can be taken in order on one keep-alive connection). `Request` has `method` and `path` (`String`), `headers` (a sequence of `Header { name, value }`), `body` (`Vec<u8>`), and `http11: bool`. `Request.header(name)` (the first value, case-insensitive) and `Request.keep_alive()` (1.1 keeps by default, 1.0 closes by default. Overridden by `Connection`). Limits: the size up to the request line and the blank line is `max_head`, and the body (`Content-Length` or the total of chunked) is `max_body`. If exceeded, `HeadTooLarge` / `BodyTooLarge` is returned and nothing more is read. For `Transfer-Encoding` only `chunked` is accepted (others are `Unsupported`), and combining it with `Content-Length` is `BadRequest`. `read_request[R: linear + std.io.Read<[io.net]>](source: &mut R, decoder: &mut Decoder)` returns one request (`None` if the connection closed at a request boundary, `Truncated` if it closed midway). `write_all[W: linear + std.io.Write<[io.net]>](out: &mut W, bytes: &[u8])`. A response is `render(status: u16, head: &str, body: &[u8], keep_alive: bool) -> Result<Vec<u8>, Error>` (`head` is additional header lines, each ending with CRLF. `Content-Length` and `Connection` are attached by the implementation). `reason(status)` is the reason phrase (an unknown number gives `Unknown`). `Error` is `Alloc` `BadRequest` `BodyTooLarge` `HeadTooLarge` `Io(std.io.Error)` `Truncated` `Unsupported`.
- `std.tls` (`spec/stdlib/std/tls.ksnl`. Loads OpenSSL's `libssl.so.3` and `libcrypto.so.3` dynamically with `extern` (`link "library:name"`, 3.8). The bundled `std` implicitly permits `unsafe`. If either is missing at run time, it is the load failure of 3.8 with exit code 101). Server: `TlsAcceptor.load(cert_file: &str, key_file: &str)` reads a PEM certificate chain and private key (`Load` if they do not match). `TlsAcceptor.accept(&self, tcp: TcpStream) -> Result<TlsStream, Error>` performs the handshake (on failure `tcp` is closed). `TlsAcceptor.close(self)`. Client: `connect(address: &str, host: &str)` and `connect_with(address, host, ca_file: &str)` verify the certificate and host name by default (if `ca_file` is empty, the default CA bundle, otherwise the CA of that PEM. `host` is also used for SNI). `TlsStream` is linear and implements `std.io.Read<[io.net]>` and `std.io.Write<[io.net]>` (one read or write is up to `MAX_CHUNK` = 16384 bytes. `read` gives `Ok(0)` at the end of the connection). `close(self) -> Result<(), std.net.Error>` sends close_notify, releases the session, and closes the TCP. `Error` is `Alloc` `Io(std.io.Error)` `Load(u64)` (the value of an OpenSSL error) `Name` (NUL in the path or host) `Net(std.net.Error)` `Ssl(i32)` (the value of `SSL_get_error`) `Verify(i64)` (the value of the verification reason). TLS is 1.2 or later.
- Convention: an allocation that returns a value returns `Result<_, alloc.alloc.AllocError>`, and on failure destroys the argument value (when the value is non-linear). `Clone.clone` is `-> Self uses [] panics never` and cannot allocate, so types that own heap memory do not implement `Clone` but implement the trait `alloc.alloc.TryClone` (`fn try_clone(self: &Self) -> Result<Self, alloc.alloc.AllocError> uses [alloc] panics never`) (`alloc.vec.Vec<T, A>` when `T: TryClone`). The trait is placed in `alloc.alloc` because `AllocError` is in the `alloc` layer and cannot be referenced from `core` (the layer order is `core` → `alloc`). A type that implements `Clone` also has `TryClone` (a built-in implication. Generic code with `T: TryClone` also accepts `Clone` types). `derive [TryClone]` is in 4.3. Iterator adapters do not have default methods on `Iterator`, and are expressed with free functions such as `core.iter.map(it, f)` and types such as `Map`.
- The standard library types that can take linear types (4.4) as type arguments are only `Option` and `Result` (and their methods), plus `std.sync.Sender` / `Receiver` / `SendError`, `std.thread.JoinHandle`, `spawn`, and `channel` (5.5) for passing between threads, and containers such as `Box` / `Vec` / `HashMap` / `Arena` hold only non-linear elements (because the container's `Drop` destroys the elements. The `T` of `Arena<T, A>` and `Handle<T>` is also limited to non-linear). `Option` / `Result` are `T: linear` (`Result` also `X: linear`), and can be used as the return types of `std.fs.open` and others that return linear values. The side that discards (the default of `unwrap_or`, the error value of `Option.ok_or`, the error value of `Result.ok`) is limited to non-linear.
- Shared handles (0.10.34. `spec/stdlib/alloc/arena.sig` and `arena.ksnl`, `設計_共有の取っ手.md`): `alloc.arena.Arena<T, A>` is a container that holds elements in a single `alloc.raw.Buf<Slot<T>, A>`, and has `insert` (a `Result` with `uses [alloc]`), `get`, `get_mut`, `remove`, `contains`, `len`, and `is_empty` (the `get` family returns `Option` and does not panic). `alloc.arena.Handle<T>` is a `Copy` value of only `index: usize` and `generation: u32`, and only the `Arena` side can create one (fields are private. Returned by `Arena.new` and `Arena.insert`). `remove` returns the element, raises the slot's generation by one, and returns it to the free list, so an old handle gives `None` from `get` (the same meaning as a weak reference. It does not dangle). `Slot<T>` is an enum of `Free(generation, next free)` and `Taken(generation, T)`, and element indices do not move on `grow` (chunks are not cut). There is no common owner (`Rc` / `Arc`) (so there are no cyclic leaks). `Handle<T>` implements `Clone` / `Copy` with a hand-written `impl[T]` (`derive [Copy]` would add `T: Copy` as a bound, making `Handle<String>` unusable). `Send` / `Sync` are in 5.5.
