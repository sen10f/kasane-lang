  - Import: the example uses `env.ksn_timer_start(ms: i32) -> u32` (creates a timer that resolves with the value 7 after `ms` and returns its number). Other JS functions can also be imported with `link "env:name"` (see "Connecting with JS" above).
  - How to verify: `node tools/wasm/run_await.mjs <file.wasm>` runs by this convention (supplies the imports, calls `ksn_main`, and, if waiting, repeats `ksn_resume` and finishes with the exit code).
- Exit codes are the same as x86_64 native: 0 for normal; if the entry is `Err(e)`, `Error: <display of e>` is written to standard error and the code is 1; a panic writes `panic: <message>` to standard error and the code is 101; when the call depth exceeds the limit (100000, 5.3), `stack overflow` is written and the code is 102.
- Unsupported features fail before generation with a reason (E9040): threads (`spawn` / `join` / channels / `Mutex`), files (`std.fs`), sockets (`std.net`), external commands (`std.process`), environment and arguments (`std.env`), real time (`std.time.SystemTime`), formatting of floating point (display and stringification. The shortest round-trip display needs libc's `snprintf` / `strtod`), and `extern` that calls C functions (FFI).
- How to verify: `node tools/wasm/run.mjs <file.wasm>` runs by the above convention (supplies the imports, calls `ksn_main`, and finishes with the exit code). `node tools/wasm/run.mjs --abi <file.wasm>` outputs the list of imports and exports as JSON. The verification of the JS connection (running the TODO SPA on a fake DOM) is `node tools/wasm/spa_check.mjs <web directory> <todo_spa.wasm> <API prefix>` (`apps/todo_spa`, `stage0/tests/wasm_spa.rs`).
- 128-bit integer multiplication, division, and shifts become libcalls such as `__multi3` by LLVM on wasm32. Their implementation is held by `src/wasm/rt.c` (the result is written to the pointer of the first argument, per LLVM's calling convention). That they give the same values and the same out-of-range errors as x86_64 is verified in `stage0/tests/wasm_spa.rs`.
- Check `ksn check --target wasm32-unknown-unknown`: range-checks `usize` / `isize` literals at 32 bits (4.5). Other checks do not change.
- The WASI section (`wasm32-wasi`, 修正プラン 5-3): `ksn build --target wasm32-wasi` turns the same LLVM IR into a WASI preview 1 `.wasm` (the triple is `wasm32-wasi`, LLVM's triple is `wasm32-unknown-wasi`, and the output is `target/wasm32-wasi/<debug|release>/<name>.wasm`). The pointer width is 32 bits, the same as the bare wasm above (4.5).
  - Imports are only functions of `wasi_snapshot_preview1` (no `env` imports are attached). The JS functions of `link "env:name"` remain imports of `env.name` under WASI too.
  - Exports are `memory`, `_start` (the entry. It calls `main` with arguments and `proc_exit`s the return value), and functions beginning with `ksn_` (the rules of "Connecting with JS" above remain). `ksn_main` is kept, as in bare wasm.
  - WASI functions used: `fd_write` (standard output, standard error, files), `fd_read`, `fd_close`, `fd_sync`, `fd_readdir`, `fd_prestat_get`, `path_open`, `path_filestat_get`, `path_unlink_file`, `path_create_directory`, `path_remove_directory`, `path_rename`, `args_sizes_get` and `args_get`, `environ_sizes_get` and `environ_get`, `clock_time_get` (real time), `random_get` (the source of `std.rand.fill_secure` and `Rng.from_entropy`), `proc_exit`.
  - Files (`std.fs`): relative paths are relative to the preopened directory (the first one found with `fd_prestat_get`). A leading `/` is dropped (absolute paths are also read as relative under the preopen). The preopened location is decided by the executor (`tools/wasm/run_wasi.mjs --dir <dir>`, the current directory if omitted). Paths that go outside the host are refused by the host.
  - Errors: the `kind` of `std.io.Error` follows the same convention as bare wasm. `code` is the OS error number, the value obtained by converting the WASI number to the Linux number (`ENOENT` is 2).
  - Arguments and environment (`std.env`): `arg_count` and `arg` follow the order of `args_get`, and `arg(0)` is the first user argument (the program name is not included). `var` is the value of `environ_get`.
  - Unsupported (E9040, with a reason. Stopped before generation): threads, `std.net` (sockets), `std.process` (external commands), display of floating point (formatting), and `extern` that calls C functions (FFI).
  - How to verify: `node tools/wasm/run_wasi.mjs <file.wasm> [args...]` runs it (`node:wasi`. The exit code is the value of `proc_exit`). `node tools/wasm/run_wasi.mjs --abi <file.wasm>` outputs the list of imports and exports as JSON. `stage0/tests/wasm_wasi.rs`.

### 8.1 Packages

`kasane.toml` (project root):

```
[package]
name = "app"
version = "0.1.0"
edition = 1
entry = "app.main"

[unsafe]
modules = ["app.sys"]
native = true

[native]
static = ["vendor/libapphelp.a"]
dynamic = ["m", "SDL3"]
search = ["vendor"]

[dependencies]
local = { path = "../local" }
pinned = { git = "https://example.org/pinned.git", rev = "0123456789abcdef0123456789abcdef01234567" }
ranged = { git = "https://example.org/ranged.git", version = ">=1.2.0, <2.0.0" }
exact = { git = "https://example.org/exact.git", version = "=1.2.3" }
registry_pkg = { registry = "https://example.org/kasane-registry.git", version = ">=1.0.0, <2.0.0" }
```

- The `name` in `[package]` must match the top-level module name (3.6). It is `[a-z][a-z0-9_]*`, and reserved words (3.7) are not allowed (a violation is E9003, a reserved-word name is E9004). `version` is `MAJOR.MINOR.PATCH` (a leading 0 other than 0 itself, pre-release, and build metadata are not allowed. A violation is E9005). `edition` is an integer. `entry` is written only for executable packages, and if omitted the package is a library.
- `[unsafe]` can be omitted, and `modules` (an array of module names) lists the modules permitted to use `unsafe`, `extern`, and raw pointers (3.5). Each element is a module name made of `[a-z][a-z0-9_]*` joined by `.`, and must be a module of the own package (the top-level component is the package name). A nonexistent entry (`ksn run`) is E9030, and an unknown key is E9007.
- A package with `[native]` (including dependencies) states `native = true` in `[unsafe]` explicitly (otherwise E9024. A C library can run code at startup). `ksn unsafe` lists all the libraries of `[native]`. The archives of `[native] static` of a `git` dependency are subject to `hash` (swapping them is E9022).
- `[native]` can be omitted, and specifies C libraries with `static` (an array of static archive paths), `dynamic` (an array of library names for `-l`), and `search` (an array of directories to search at link time) (3.8). Relative paths are from the package root. The canonical order of sections is `package, unsafe, native, dependencies`, and of keys `static, dynamic, search` (`ksn fmt` / E0020). An unknown key is E9007, and a malformed shape (not a table, not an array, not a string, empty or beginning with `-`, a `:` in `dynamic`, path separators, extensions) is E9012. The `[native]` of a dependency package is not used for linking, and for `git` dependencies it is recorded in `native_libs` and compared (below).
- The keys of `[dependencies]` are dependency package names (their top-level module names). The way of writing is only the following single form.
  1. The source is exactly one of `path`, `git`, and `registry`.
  2. `path` cannot have `rev`, `version`, or `tag`.
  3. `git` has exactly one of `rev` and `version`. `rev` is 40 lowercase hex digits, and `version` is the range expression below.
  4. `registry` requires `version`. Another registry is specified directly by URL, and no aliases or implicit registries are introduced.
  5. Shorthand such as `name = "1.2.3"`, branches, HEAD, and the `tag` key are not adopted. Git versions are limited to semver tags.
  6. No alternative notations with the same meaning are allowed for dependency names, URLs, or versions. An unknown key is E9007, and an error in type, range, URL, or `rev` is E9008.
- The range grammar usable for dependency versions is only the following one.

```
range      := comparator ("," comparator)*
comparator := ("=" | ">=" | "<=" | ">" | "<") version
version    := MAJOR "." MINOR "." PATCH
```

  - The only examples of ranges are `=1.2.3` and `>=1.2.0, <2.0.0`. Whitespace between comparators is only in the form `, `. No whitespace is placed between a comparator and a version.
  - Each version is decimal integers of `MAJOR.MINOR.PATCH`. A leading 0 other than 0 itself, pre-release, and build metadata are not adopted.
  - `^`, `~`, `*`, `x`, hyphen ranges, `||`, and npm's compound forms are not adopted.
  - Git candidate tags are strictly only `vMAJOR.MINOR.PATCH`. `v1.2` and `release-1` are not versions. A wrong tag is E9008.
  - If several tags or commits match the same semver, neither the Git side nor the registry side selects automatically, and it is a duplicate error.
