# 設計 D1: 共有の取っ手 (Rc/Arc 相当 vs アリーナ+世代つきハンドル)

2026-11-19。読み取り専用の設計。対象: `docs/design/設計_ネイティブUI.md` N3/N5 の「共有の持ち主」「C コールバックの user data」。現状: 共有所有権なし (5.5 はチャネルと `static Mutex` で代用する方針)、参照は二級 (E3060、`docs/design/設計_二級の参照.md`)。

## 1. 前提 (現状の制約)

- 参照は二級: `&T` は引数・戻り値・局所だけ。型の欄・容れ物 (`Vec` `Box` `std.sync.*` …) の型引数には RC を入れられない (E3060)。標準の寿命つき組み込み型 (`MutexGuard<'a, T>` など) だけが例外。
- コンテナ (`Box` `Vec` `HashMap` …) は線形な要素を持てない (8.3。Drop が要素を捨てるため)。線形型を渡せるのは `Option` / `Result` / チャネル / `JoinHandle` だけ。
- 確保は `uses [alloc]` で `Result` (panic しない)。解放は副作用でない。Drop は `uses [] panics never`。
- `Send` / `Sync` は自動導出 (生ポインタを持つと自動で不成立) + `unsafe` 許可モジュールの手動 `impl` (5.5)。
- スレッドは 2 つの実行意味 (協調 / 実スレッド、5.5)。決定性が要るテストは `ksn test --both` で両方一致が要る。
- 書き方は 1 通り (設計原則 5): 同じ意味を 2 つの道具で書ける形にしない。

## 2.選択肢の比較

### (a) `alloc.rc.Rc<T, A>` / `std.sync.Arc<T, A>` (参照カウント)

- 形: `type alloc.rc.Rc[T, A: alloc.alloc.Allocator] pub { allocator: A, pointer: *mut u8 }` (Box.sig と同じ形)。アクセスは二級の参照と両立させるため閉包でだけ渡す: `rc.with(|v: &T| ..)` / `with_mut` (単独のときだけ)。`&T` を欄に持つ guard 型を足すと「2 通りの書き方」になるので `with` 1 本にする。
- Soundness: 循環参照は回収されず恒久にリークする (GC なし)。安全ではあるが、UI のように状態が循環しがちな構造では設計上の臭い。`T: linear` はコンテナ規則で拒否 (Box と同じ)。`Rc` は生ポインタを持つので自動で `!Send / !Sync` (正しい)。`Arc` は `core.sync` のアトミックでカウントし、手動 `impl [T: Send + Sync] Send/Sync`。
- 効果: `new` は `uses [alloc]` で `Result`。`clone` は `uses [] panics never` (Rc は単純加算、Arc はアトミック)。`with` は渡した閉包の効果をそのまま負う (既存の `Fn` 効果規則で足りる)。
- 検査: E3060 の RC リストに `alloc.rc.*` / `std.sync.Arc` が**最初から入っている** (仕様 4.1)。線形コンテナ規則のリストに足すだけ。新しい診断はほぼ要らない。
- 実行系: インタプリタは内部がもう `Rc<RefCell<..>>` なので安い。KIR/LLVM は Box に「カウンタ欄 + Drop で減算」を足すだけだが、Arc はアトミック命令の KIR lowering と「別スレッドからの解放」が要る。循環リークの検出はできない。

### (b) アリーナ + 世代つきハンドル (`alloc.arena.Arena<T, A>` / `Handle<T>`)

- 形: `Handle<T>` は `Copy` の平な値 (`index: usize` + `generation: u32`)。欄・`Vec`・引数にそのまま入れられる (RC でも寿命つきでもない)。`Arena<T, A>` が全値を所有し、ハンドルは添字。ちょうど gpui の `Entity<T>` の意味。
- Soundness: 循環はそもそもリークしない (アリーナが全スロットを無条件に破棄する。参照カウントがないから)。`remove` 後のハンドルは世代が合わず `get` が `None` (dangling はメモリ安全上の事故にならない)。`T: linear` はコンテナ規則で拒否 (Arena の Drop が捨てるため)。`Handle<T>` 自体は整数のみなので自動 `Send + Sync` — 単体では何のアクセスも与えないので安全。アクセスは `&Arena` 経由で、Arena は手動 `impl [T: Send, A: Send] Send` のみ。
- 効果: `insert` だけ `uses [alloc] panics never` で `Result<Handle<T>, AllocError>`。`get` / `get_mut` / `remove` / `contains` は `uses [] panics never` (`Option` で返す)。スレッド効果なし → 协調/実スレッドの 2 意味で必ず同じ結果 (`ksn test --both` が書きやすい)。
- 検査: E3060 のリストと線形コンテナ規則のリストに `alloc.arena.*` を足すだけ。新しい診断コードは**要らない**。
- 実行系: インタプリタは `Val::Arena(Rc<RefCell<Vec<Chunk>>>)` で、チャネル/Mutex と同じ natives に載せる (安い)。KIR/LLVM はチャンク制の生確保 (`alloc.raw.Buf` と同じ土台) + スロット `{generation, occupied, value}` + Drop glue (生きたスロットを回って破棄してチャンクを解放。Vec の drop に近い)。アトミック不要。
- C コールバックの user data: 新しい言語機能なしで既存の 3.8 の pattern でできる — 登録時に `core.ptr.from_mut(&mut arena)` と、ハンドルを `Box<Handle<T>>` に入れた安定セルの `*mut Handle<T>` を `layout c` の構体で値渡し。コールバックは `core.ptr.read` で `Handle<T>` (Copy) を読み、`arena.get(h)` する。契約 (arena が登録より長生き) は今の `from_mut(&mut acc)` と同じ unsafe の契約。

### (c) 両方

- `Rc` とアリーナは単一スレッド内の「共有」で意味がかぶる → 「書き方は 1 通り」に反する。検査面 (リスト) は安いが、KIR 側は参照カウント+アトミックとアリーナの両方を保守することになる。今の N3/N5 の需要は (b) だけで満たせる。

| 観点 | (a) Rc/Arc | (b) アリーナ | (c) 両方 |
| --- | --- | --- | --- |
| 循環 | 恒久リーク (安全だが) | しない (arena が全部破棄) | (b) に同じ |
| linear T | コンテナ規則で拒否 | 同左 | — |
| Send/Sync | Rc は自動 !Send、Arc は手動 impl + アトミック | Handle は自動、Arena は手動 Send のみ | 両方保守 |
| 効果/panic | new のみ [alloc]、clone [] | insert のみ [alloc]、他は [] never | — |
| 新規診断 | ほぼなし (リスト済みの名前あり) | なし (リスト追加のみ) | (a)+(b) |
| インタプリタ | 安い (内部表現が既に Rc) | 安い (チャネル/Mutex と同じ natives) | 2 倍 |
| KIR/LLVM | Box+カウンタ、Arc はアトミック必須 | Buf 似のチャンク+スロット+drop glue | 両方 |
| 決定性 (5.5) | Arc は実スレッドでのみ意味がある | 効果がないので両実行で一致 | — |
| C user data | `*mut Rc` を渡すか leak。再構築が不自然 | Handle が Copy で `layout c` にそのまま入る | — |
| 1 通りの原則 | (b) とかぶる | これが単一の道 | 反する |

## 3. 推奨: (b) アリーナ + 世代つきハンドルのみ。(a) は当面入れない

理由: N3 の 2 つの需要 (UI の共有状態ハンドル、C の user data) がどちらもハンドルで解ける。参照カウントがないので循環リークもアトミックもなく、KIR の仕事が最小で、決定性が 5.5 の 2 実行で壊れない。スレッド間の共有は現行どおりチャネルで (5.5 の方針のまま)。`alloc.rc.*` / `Arc` の名前は E3060 に予約済みなので、将来本当に必要になったら (a) を足す余地は残す (そのとき改めて 1 通りかを判断する)。

## 4. API (規範シグネチャ案 `spec/stdlib/alloc/arena.sig`)

```
type alloc.arena.Handle[T] derive [Debug, Clone, Copy, PartialEq, Eq, Hash] pub
    index: usize
    generation: u32
end alloc.arena.Handle

type alloc.arena.Arena[T, A: alloc.alloc.Allocator] pub
    allocator: A
    chunks: *mut u8
    chunk_len: usize
    chunk_cap: usize
    slots: usize
end alloc.arena.Arena

impl[T: core.marker.Send, A: alloc.alloc.Allocator + core.marker.Send] core.marker.Send for alloc.arena.Arena<T, A>
impl[T, A: alloc.alloc.Allocator] core.ops.Drop for alloc.arena.Arena<T, A>

fn alloc.arena.Arena.new[T, A: alloc.alloc.Allocator](allocator: A) -> alloc.arena.Arena<T, A> uses [] panics never pub
fn alloc.arena.Arena.insert[T, A: alloc.alloc.Allocator](self: &mut alloc.arena.Arena<T, A>, value: T) -> Result<alloc.arena.Handle<T>, alloc.alloc.AllocError> uses [alloc] panics never pub
fn alloc.arena.Arena.get[T, A: alloc.alloc.Allocator](self: &alloc.arena.Arena<T, A>, h: alloc.arena.Handle<T>) -> Option<&T> uses [] panics never pub
fn alloc.arena.Arena.get_mut[T, A: alloc.alloc.Allocator](self: &mut alloc.arena.Arena<T, A>, h: alloc.arena.Handle<T>) -> Option<&mut T> uses [] panics never pub
fn alloc.arena.Arena.remove[T, A: alloc.alloc.Allocator](self: &mut alloc.arena.Arena<T, A>, h: alloc.arena.Handle<T>) -> Option<T> uses [] panics never pub
fn alloc.arena.Arena.contains[T, A: alloc.alloc.Allocator](self: &alloc.arena.Arena<T, A>, h: alloc.arena.Handle<T>) -> bool uses [] panics never pub
fn alloc.arena.Arena.len[T, A: alloc.alloc.Allocator](self: &alloc.arena.Arena<T, A>) -> usize uses [] panics never pub
fn alloc.arena.Arena.is_empty[T, A: alloc.alloc.Allocator](self: &alloc.arena.Arena<T, A>) -> bool uses [] panics never pub
fn alloc.arena.Arena.drop[T, A: alloc.alloc.Allocator](self: &mut alloc.arena.Arena<T, A>) -> () uses [] panics never impls core.ops.Drop
```

補足:

- チャンク制 (スロットを動かさない) にする。`insert` は空きスロット (前に `remove` した所) を世代を 1 つ上げて再利用し、なければチャンクを伸ばす (`uses [alloc]`)。世代はスロットごとに記録し、`remove` で増やす。
- `get` の `Option<&T>` は `&self` に結ぶ省略形で書ける (4.1 の正規形)。返した参照は局所でだけ生きるので二級の参照と両立する。`Handle` に `&T` を入れるのは E3060 (リスト追加で拒否)、`Arena<T: linear>` / `Handle<T: linear>` は線形コンテナ規則で拒否。
- `Handle[T]` の `T` が欄に現れない場合 (unused type param) は処理系の規則に従う。拒否されるなら `core.marker.PhantomData`-相当の 0 サイズ欄を足すか、`Handle` を非総称にして `Arena.get::<T>` 形にするかのどちらか (実装時に決める。意味は同じ)。
- 弱ハンドルは不要: `remove` 済みのハンドルはそのまま「弱」で、`get` が `None` を返す。
- C 橋渡し (新 API なし、3.8 の pattern): 登録側で `layout c` の構体 `{ arena: *mut u8, cell: *mut alloc.arena.Handle<T> }` を値渡し。`arena` は `core.ptr.from_mut(&mut arena)`、`cell` は `alloc.boxed.Box.new(alloc, h)?` の `Box.as_mut` から `core.ptr.from_mut`。コールバック (capture []、`uses [] panics never`) は `core.ptr.read` で Handle を読み `arena.get(h)`。契約は既存の unsafe 契約と同じ。

## 5. 検査に要るもの (新規診断はゼロの見込み)

1. `refs_check.rs` の E3060 の RC を運ぶ型のリストに `alloc.arena.*` を足す (宣言の欄・容れ物の型引数・参照取り込み閉包の 3 箇所すべてに効く)。
2. 線形な型引数を拒むコンテナ規則 (8.3) の対象リストに `alloc.arena.Arena` / `alloc.arena.Handle` を足す (`Arena<linear>` と `Handle<linear>` を拒否)。
3. `Send`/`Sync`: Arena の手動 `impl` (生ポインタがあるので自動導出は不成立のまま) を `unsafe` 許可モジュールの `.sig` に置く。Handle は自動で Send+Sync (整数のみ) でよいことを仕様 5.5 に 1 行追記。
4. 型の一致は既存の仕組みで通る (`Handle<T>` と `Arena<T, A>` の T が違えば型エラー)。世代の食い違いは実行時 `None` なので静的には出ない。

## 6. KIR lowering に要るもの

- 型の lowering: `Arena` は集成体 (アロケータ + チャンク配列の ptr/len/cap + スロット数)。チャンクは `A.alloc` で確保した生メモリで、スロットは `{ generation: u32, occupied: u8, value: T }` (未占有時の value は undef で、occupied を先に読むので読まない)。`alloc.raw.Buf` と同じく `unsafe`許可モジュール内に閉じる。
- 命令: フィールドアクセスは既存の集成体命令で足りる。`insert` は `alloc` 呼び出し + 配列への store、`get` は load + 世代比較 + 分岐。新しい KIR 命令は要らない見込み。
- Drop glue: `kir_lower_drop.rs` と同じ形で、全チャンクを回って occupied な値を破棄し、最後にチャンクを `A.dealloc`。再帰型の T でも回せる (反復で回る。Vec の drop glue に近い)。循環していても全部解放される。
- `ksn run` との一致は既存の方針で取る (`kir_*` テスト)。最初の版はネイティブ非対応なら理由つきでバンドル退避でもよいが、Arena は単純なので LLVM 対応は難しくない。

## 9. (a) を後で入れる場合のためのメモ (今は実装しない)

`alloc.rc.Rc<T, A>` は `with[R, F: Fn<(&T,), R, E, P>](&self, f: F) -> R uses [E] panics P` 形式で借りを渡す (guard 型は足けない。1 通りのため)。`Arc` は `std.sync` に置き、アトミックカウント + 手動 Send/Sync。循環リークは仕様に「回収しない」と明記する。いずれも E3060 のリストに名前がもう入っているので、将来の追加はリストと natives/KIR の実装だけで済む。
