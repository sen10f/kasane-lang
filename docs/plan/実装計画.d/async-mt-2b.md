# async-mt-2b: ネイティブの実スレッド実行器 (block_on_threads の n 本のワーカー)

ブランチ `task/async-mt-2b` (土台 `task/async-mt`)。設計は `docs/design/設計_多重化したネット.md` 9〜17 章、下調べは `async-mt.md`。

## 作りと結果 (2026-11-24)

- **共有の核** (`sysrt.c` の `ksn_rt_sys_mt_*`、Linux だけ。1 本の mutex + cond): 注入列 (まだ始まっていないタスク)、項目 (状態 0 待ち / 1 走行中 / 2 終わり / 3 取り消し、枠、取り消しの印)、世代 `epoch`、止めの旗、未完了数、眠りと全員待ちの検出 (`ksn_rt_sys_mt_sleep(seen)`: 世代が `seen` のままなら眠る。眠っている数が `n` になったら 3 = deadlock。出来事 = push / finish / cancel / stop は世代を進めて数を 0 に戻す)。タスクの id は `項目の番地 | 2^62` (ローカルの id は表の添字なので重ならない)。
- **ワーカー**: 各ワーカーは今の 1 スレッドの実行器 (`ksn.task.g` は LLVM の下ろしでスレッドごと) をそのまま持ち、`ksn.task.mt_loop` を回す。ルート = ワーカー 0 (呼び出したスレッド)、残り `n - 1` 本は既存のスレッドの補助 (`ksn.thr.new/ent/start/join`) で起こす (入口 `ksn.thr.site.ksn.task.worker`、`kir_lower_task::pre_finish` が `thread_lower::finish` の前に足す)。
- **横取り**: 始まっていないタスクだけ。`spawn` は注入列へ積み、ワーカーは (走れる局所のタスクが無いとき・8 周に 1 回) 注入列から 1 つ取って自分の表へ登録する。始まったタスクはそのワーカーに居続ける (リアクター = epoll もスレッドごとなので、共有の epoll は要らない。IO の待ちがあるワーカーは `epoll_wait` を 1 ms 以下で回して注入列・完了を見直す)。
- **join**: 項目の状態を atomic で読む。待ち手のワーカーは局所の表で待ち、`ready` が項目の状態を見る。
- **取り消し**: 始まる前なら状態を 3 にして枠を捨てる。始まっていれば印を立て、そのワーカーが次の周で (待ち中のタスクも `ready` が印を見る) 中断点で抜ける (枠と葉を解放)。同期ではない点が仕様 5.6 の「取り消し」の文と違う (取り消した直後に走り続ける可能性がある)。
- **終了**: ルートが「ルートが終わった・局所が全部終わり・未完了数 0」を見て stop を立てる。ワーカーは止めの旗と局所の終わりで抜け、ルートが join する。
- **全員待ち**: 眠る直前の世代 = 眠りに渡した世代で、全員が眠ると 3 → `deadlock: every std.task task ...` の panic (101)。IO の待ちがあるワーカーは眠らない (ソケットが来るかもしれないので deadlock にしない)。
- **panic**: ワーカーのタスクの panic はメッセージを出して 101 (既存のスレッドの入口の経路)。
- 参照 (木走査・KIR 参照実行器) は `ksn.mt.*` が KIR の本体 (偽・協調) のままなので決定的で `n` を無視する。Windows / wasm は `ksn.mt.*` を差し替えない (E9040 の経路は従来どおり)。
- 副産物: `sysrt.c` の期限の表 `ksn_dls` を mutex で保護、`ksn_to_set` を atomic に (TSan の競合)。poll で期限の表を走査するのは期限つきの待ちを一度でも載せたスレッドだけ。

## 試験 (`stage0/tests/net_async_mt.rs`)

n=4 / 16 / 1 の echo (256 接続 = 厳密なバイト)、10 万タスクの合計、ワーカーの panic = 101 とメッセージ、取り消し (走行中・始まる前)、全員待ちの核 (C の直接試験)、TSan (echo n=4/16、stress、cancel) が競合 0。

## 既知

- 木走査 (`ksn run --engine=tree`) が取り消しの試験で 1/40 ほど `malloc_consolidate(): unaligned fastbin chunk` で落ちる (土台の `task/async-mt` でも 1/40 で出る。2b の変更とは無関係。木走査の `cancel` + スレッドの問題)。
- ソースから「全員待ち」を作る手段がネイティブにはまだ無い (`Task` を `Receiver` や `static` に載せる形が下ろせない) ので、実行器の全員待ちは C の核の試験 + 木走査の協調実行の文言で確かめている。
