# 実装計画メモ: branch std/o07-env-log (worktree /home/kasane/kasane-wt/o07)

## 対象
opus-vuln 2 回目の low 2 件 (report.md "2 回目"):
- O-07: `std.process.Command.env` が鍵の `=` / 空鍵を受け付け、`LD_PRELOAD=/evil/x.so:` が拒否リストの完全一致をすり抜ける。
- L-03: `std.log.*` のユーザ欄が予約の `level`/`ts`/`msg` と衝突し、JSON 読み手で後勝ちされ水準・時刻を偽れる。

## 方針
- O-07: 署名 `Command.env(key, value) -> ()` は `Result` を返せない (既定通り変更しない)。`env`/`env_remove` で鍵が空・`=` を含む (鍵・値とも NUL も) なら命令表を `bad` にし、`spawn`/`output` が既存の `InvalidInput` パスで失敗する。ネイティブ (`sysrt.c` `ksn_rt_sys_proc_cmd` の `P_ENV`/`P_ENV_REMOVE`) も同じ条件で `c->bad = 1` (`pdup` は既に NUL で bad)。interp と native で同じ挙動。`process.sig` は変更しない。
- L-03: `std.log.line` でユーザ欄の鍵が `ts`/`level`/`msg` と衝突したら `Err(std.io.Error { kind: InvalidInput, code: 0 })` (失敗閉塞。既存の `std.io.Error` パス。署名変更なし)。`log.ksnh` の注釈 (鍵は検査しない) を直す。`.ksnl` はコメント無しなので変更無し (`strip` と整合)。interp/native とも Kasane 標準ライブラリなので 1 箇所。
- テスト追加: `stage0/tests/process.rs` (O-07, interp + LLVM ネイティブ), `stage0/tests/time_log.rs` (L-03, interp + LLVM ネイティブ). 新しい診断コードは追加しない (`diag/` や `explain` は不要)。
